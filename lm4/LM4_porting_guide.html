0. 개요 — 왜 까다로웠나

LM4-driver 소스는 intel fpp 전용으로 쓰여 있어(ISO cpp # stringify / ## token-paste를 디버그 + DEFINE_*_ACCESSOR 매크로에 광범위 사용) gfortran으로는 그대로 빌드되지 않는다. 핵심 해법은 LM4 소스만 intel fpp로 전처리한 뒤 gfortran으로 컴파일하는 것. 또한 라이브러리 스택은 spack-stack(gcc)으로 직접 빌드한다.

3. 소스/빌드 패치 (★ 재현 시 반드시 재적용 — git submodule update 시 사라짐)

3-1. FindESMF: ESMF::ESMF 타겟 생성

CMakeModules/Modules/FindESMF.cmake(구버전 스텁)가 변수만 세팅하고 imported 타겟을 안 만들어 UFS/CDEPS/CMEPS/LM4가 링크하는 ESMF::ESMF를 못 찾는다. 파일 끝에 추가:

if (ESMF_FOUND AND NOT TARGET ESMF::ESMF)
  string(STRIP "${ESMF_F90ESMFLINKRPATHS} ${ESMF_F90ESMFLINKPATHS} ${ESMF_F90ESMFLINKLIBS}" ESMF_INTERFACE_LINK_LIBRARIES)
  add_library(ESMF::ESMF INTERFACE IMPORTED)
  set_target_properties(ESMF::ESMF PROPERTIES
    INTERFACE_INCLUDE_DIRECTORIES "${ESMF_F90COMPILEPATHS}"
    INTERFACE_LINK_LIBRARIES "${ESMF_INTERFACE_LINK_LIBRARIES}")
endif()

3-2. ★ LM4를 intel fpp로 전처리 (핵심)

gfortran 통합 전처리기는 traditional 모드라 #/## 연산자를 지원하지 않는다. LM4-driver/CMakeLists.txt의 include("lm4_src_files.cmake") 다음, add_library(lm4 ...) 앞에 삽입:

if(CMAKE_Fortran_COMPILER_ID MATCHES "GNU")
  set(FPP_EXE "/usr/local/intel/oneapi/compiler/latest/linux/bin/intel64/fpp")
  set(FMS_INC "/data2/ydkoh/spack-stack/spack/opt/spack/linux-sapphirerapids/fms-2025.03-dksylqkysm2ngh3mlon7d4fbu334hpca/include_r8")
  set(_lm4_pp_srcs "")
  foreach(_src ${lm4_src_files})
    get_filename_component(_ext ${_src} EXT)
    if(_ext STREQUAL ".F90")
      get_filename_component(_nm ${_src} NAME_WE)
      get_filename_component(_dr ${_src} DIRECTORY)
      set(_out "${CMAKE_CURRENT_BINARY_DIR}/fpp/${_dr}/${_nm}.f90")
      get_filename_component(_outdir ${_out} DIRECTORY)
      file(MAKE_DIRECTORY ${_outdir})
      add_custom_command(OUTPUT ${_out}
        COMMAND ${FPP_EXE} -P -DINTERNAL_FILE_NML -DMPI -I${FMS_INC} ${_nm}.F90 ${_out}
        WORKING_DIRECTORY ${CMAKE_CURRENT_SOURCE_DIR}/${_dr}
        DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/${_src} VERBATIM)
      list(APPEND _lm4_pp_srcs ${_out})
    endif()
  endforeach()
  set(lm4_src_files ${_lm4_pp_srcs})
endif()

fpp가 .F90→.f90(소문자, 순수 Fortran)으로 전개 → gfortran은 .f90을 추가 전처리 없이 컴파일. LM4엔 컴파일러 분기 cpp가 없어 fpp의 intel 매크로는 무해. (이 방식이면 아래 3-3의 수동 디버그 패치는 사실 불필요하나 무해.)

3-3. ★ lm4_cap.F90 할당 순서 버그 (SEGV)

nuopc_cap/lm4_cap.F90 InitializeAdvertise에서 init_driver(→compute_gust가 atm_forc%gust에 값 대입)가 alloc_atmforc(gust 할당)보다 먼저 호출됨 → 미할당 포인터 접근 → segfault. intel은 우연히 안 죽던 잠복버그. alloc_atmforc 블록을 init_driver 앞으로 이동.
      call land_model_init( ... )
      call alloc_atmforc(lm4_model%atm_forc)        ! ← init_driver 앞으로 이동
      if (debug_cap > 0) call alloc_atmforc2d(lm4_model%atm_forc2d)
      call init_driver(lm4_model)
      call ESMF_LogWrite('======== COMPLETED land_model_init ==========', ESMF_LOGMSG_INFO)

4. cmake 설정 (APP=LND-LM4)

함정 ② 컴파일러: cmake가 시스템 gcc 8.5(UFS는 ≥9 요구)를 잡으므로 MPI 래퍼를 강제 지정.
spack load /3cfkk4a /dksylqk /snsodk7 /y5kptwe /4kwzqxv /kycgq3h /evn6nxf
setenv CC mpicc; setenv CXX mpicxx; setenv FC mpif90
cd /data2/ydkoh/lm4/ufs-weather-model
rm -rf build; mkdir build; cd build
cmake -DAPP=LND-LM4 \
      -DCMAKE_C_COMPILER=mpicc -DCMAKE_CXX_COMPILER=mpicxx -DCMAKE_Fortran_COMPILER=mpif90 \
      -DCMAKE_EXE_LINKER_FLAGS="-L/lib -Wl,-rpath,/lib -lhdf5_mpi_hl -lhdf5_mpi" ..
함정 ③ 링크: ESMF link line이 netcdf만 갖고 hdf5/pio를 빠뜨림 + PIO와 ESMF가 서로 다른 netcdf/hdf5 사본에 빌드됨. netcdf-c가 parallel이라 libhdf5_mpi 필요 → 위 CMAKE_EXE_LINKER_FLAGS로 명시. <hdf5> = parallel hdf5 설치 경로(libhdf5_mpi.so 보유).

5. make (fpp 전처리 + 컴파일 + 링크)

cd build; make -j6      # 산출물: build/ufs_model (~24MB ELF)

make 환경에 LIBRARY_PATH로 pio/hdf5 lib 추가 권장. 100% 컴파일 후 ufs_model 링크.

8. 런 디렉토리 구성 (rt 프레임워크 재사용)

rt.sh는 이 서버에서 안 도므로, framework의 변수정의 + atparse를 source하는 드라이버로 config를 생성한다. 핵심 변수: 케이스 datm_cdeps_lm4_gswp3 (cold start, 2000-01-01, 48h, C96, 2×2 layout) → PET: ATM(datm)·MED(cmeps)·LND(lm4) 전부 0 23 → mpirun -np 24.

#!/bin/bash   # setup_lm4_run.sh (요지)
export PATHRT=.../ufs-weather-model/tests
export RUNDIR=/data2/ydkoh/lm4/RUN/lm4_gswp3
export INPUTDATA_ROOT=/data2/ydkoh/lm4/INPUTDATA/input-data-20251015
export INPUTDATA_LM4=$INPUTDATA_ROOT/LM4_input_data
export THRD=1 TPN=40 atm_omp_num_threads=1 lnd_omp_num_threads=1 med_omp_num_threads=1
cd $PATHRT; source default_vars.sh; source rt_utils.sh; source atparse.bash
source $PATHRT/tests/datm_cdeps_lm4_gswp3
export ESMF_THREADING=false ; export ATM_tasks=$ATM_compute_tasks
compute_petbounds_and_tasks_traditional_threading
rm -rf $RUNDIR; mkdir -p $RUNDIR; cd $RUNDIR
atparse < $PATHRT/parm/$INPUT_NML            > input.nml
atparse < $PATHRT/parm/$MODEL_CONFIGURE      > model_configure
atparse < $PATHRT/parm/$UFS_CONFIGURE        > ufs.configure ; sed -i '/_omp_num_threads:/d' ufs.configure
atparse < $PATHRT/parm/diag_table/$DIAG_TABLE > diag_table
cp      $PATHRT/parm/field_table/$FIELD_TABLE_ADDITIONAL field_table
cp      $PATHRT/parm/fd_ufs.yaml              fd_ufs.yaml      # ← 함정 ⑤: 빠뜨리면 YAML read 실패
atparse < $PATHRT/parm/$DATM_IN_CONFIGURE    > datm_in
atparse < $PATHRT/parm/$DATM_STREAM_CONFIGURE > datm.streams
for i in $FV3_RUN; do atparse < $PATHRT/fv3_conf/$i >> fv3_run; done
bash ./fv3_run                                                # INPUT/ staging (tar 풀기·링크·rsync)
rsync -a $INPUTDATA_ROOT/MOM6_FIX/100/ INPUT/                 # ← 함정 ⑥: ocean_mosaic.nc

10. 결과 확인

런 디렉토리 /data2/ydkoh/lm4/RUN/lm4_gswp3/:

  • LM4 land 진단 (핵심): YYYYMMDD.land_hourly.tile1-6.nc — 시간별. 변수: vegn_T, LAI, npp, gpp, soil_liq, soil_ice, runf, precip, snow_soil… (동적식생 LAI/NPP/GPP 포함)
  • land_month.tile?.nc(월평균), land_static.tile?.nc(정적)
  • 커플러: ufs.cpld.cpl.hi*.nc, ufs.cpld.cpl.hi.lnd*.nc
  • Restart: RESTART/*.res.tile?.nc (6h마다 + 최종 48h)
출력은 C96 cubed-sphere 6타일 → 분석/도시는 lat-lon regrid 필요 (ESMF/CDO/fregrid). 검증은 같은 컴파일러(gfortran) 내 재현성으로 — intel 공식 baseline과는 부동소수점 roundoff 차이로 bit-identical 아님.
