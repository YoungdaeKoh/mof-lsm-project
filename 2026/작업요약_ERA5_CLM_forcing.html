해수부 세부 1.7 — ERA5 → CLM 대기강제력(forcing) 구축

작업기간: 2026-06-16 ~ 06-17 · 작성: ydkoh · 과제: 차세대 해양기후모델 지면-식생모델 진단

🎯 1차년도 deliverable 연결 — ② 평가용 자료 DB(forcing) + ③ offline simulation. 다중 LSM 테스트베드 중 CLM5의 ERA5 강제력을 GSWP3 포맷으로 구축하고 1979 1년 적분 완주.

1. 목표

raw ERA5(0.25°, 시간별)를 CLM5 offline 구동용 대기강제력으로 변환. 기존 GSWP3 datm 스트림 포맷에 그대로 끼울 수 있게 제작 → CLM datm이 읽어 offline 적분.

  • 코드: era5_to_clm5.ncl (climate00 /data2/ydkoh/2026_MOF_LSM/Atm_forc/1_CLM/)
  • 출력: 연 1파일 YYYY_era5.nc (0.5°, 6-hourly, 7변수 + 격자메타)
  • 설계: 코드1(공용 물리변환) / 코드2(모델별 포맷) 분리 개념 — 현재 CLM은 단일 스크립트로 통합

2. 변환 파이프라인

raw ERA5 0.25°(721×1440, lat 내림차순, short 패킹) → 변수환산 → lat flip(S→N) → 보존 regrid 0.5°(360×720, GSWP3 domain) → noleap time → NetCDF4Classic 저장.

CLM 변수ERA5 입력처리
TBOTt2m그대로 (K)
PSRFsp그대로 (Pa)
QBOTd2m + sp비습 환산 e=611.21·exp(17.502(Td−273.16)/(Td−32.19)); q=0.621981e/(sp−0.378e)
WINDu10, v10√(u²+v²), 합성 후 regrid
FLDSavg_sdlwrf그대로 (W/m², 6-hourly avg)
FSDSavg_sdswrf (hourly)hourly mean flux → 6h 평균 (초기 ssrA÷3600은 폐기)
PRECTmmstp (hourly)6 hourly 합 ×1000 ÷21600 → kg/m²/s
공통 처리: ① short2flt로 언패킹(NCL 자동 안 함) · ② lat 90→−90 이라 regrid 전 (:,::-1,:) flip 필수 · ③ 윤년 drop_feb29로 2/29 제거(CLM noleap, 1460 step) · ④ time ispan(0,nt-1)*0.25+0.125 (구간중심) · ⑤ 격자메타 LONGXY/LATIXY/EDGE는 GSWP3 domain에서 복사.

2.5 처리 흐름도 (한눈에)

[ Input ] ERA5 Hourly 0.25°  (t2m, d2m, sp, u10, v10, avg_sdswrf, avg_sdlwrf, tp)
   │
   ▼
[ Step 1. Load & Pre-process ]
   ├─ 파일 일괄 읽기 (addfiles, ListSetType cat)
   ├─ short2flt 언패킹 + 위도 역순 정렬 (::-1, → S→N)
   └─ 윤일(Feb 29) 제거 (drop_feb29, noleap)
   │
   ▼
[ Step 2. Variable Calc & Temporal Aggregation ]
   ├─ TBOT  ← t2m (그대로)
   ├─ PSRF  ← sp  (그대로)
   ├─ QBOT  ← d2m, sp 로 수증기압 e → 비습 q 계산
   ├─ FLDS  ← avg_sdlwrf (그대로, 6h avg)
   ├─ FSDS  ← avg_sdswrf 6시간 평균 (dim_avg_n_Wrap, flux)
   ├─ PRECTmms ← tp 6시간 누적 (dim_sum_n_Wrap) → kg/m²/s
   └─ WIND  ← √(u10² + v10²)
   │
   ▼
[ Step 3. Spatial Regridding ]
   ├─ Target = GSWP3 0.5° 2D 격자 (LATIXY, LONGXY)
   └─ area_conserve_remap_Wrap 로 7변수 보존 보간 (0.25°→0.5°)
   │
   ▼
[ Step 4. Metadata & Time Axis ]
   ├─ 6-hourly time 배열 (ispan*0.25+0.125, noleap)
   └─ setmeta: 1D 좌표 제거 + CLM5 변수명/단위 부여
   │
   ▼
[ Output ] NetCDF4Classic  yyyy_era5.nc
   └─ 7변수 + 2D 격자/경계 (LONGXY/LATIXY/EDGEE/W/S/N) + time(noleap)

※ 초기엔 FSDS=ssrd÷3600(6h-1h샘플)이었으나 CLM longwave balance 크래시 유발 → hourly avg_sdswrf(mean flux) 6h평균으로 교체. 출력은 NetCDF4Classic(datm 호환·NC_CHAR calendar) 필수.

3. ★ 디버깅 — 출력 포맷이 핵심 함정이었음

forcing 데이터(값·격자·time)는 정상인데 datm이 거부. 출력 NetCDF 포맷 때문. 두 단계로 드러남:

포맷증상원인
LargeFile (64-bit offset/CDF-2)shr_stream_verifyTCoord: elapsed seconds must be increasing (하루 경계서 secs 75600→10800 리셋)datm이 time 좌표 오독. ncdump·cd_calendar는 정상이라 혼란
NetCDF4shr_stream_getCalendar: nf90_get_att calendarcalendar 속성이 NC_STRING으로 기록됨 (datm은 NC_CHAR 기대)
NetCDF4Classic ✅정상 — datm 읽고 런 완주HDF5기반(2GB 한계 없음) + classic모델(NC_STRING 없음 → 속성 NC_CHAR)
교훈 — CLM forcing 출력은 setfileoption("nc","Format","NetCDF4Classic"). 검증: ncdump -k → netCDF-4 classic model, time:calendar="noleap"(string 표기 없이). GSWP3 원본은 classic(CDF-1) monthly라 둘 다 비껴감.

그 외 잡은 이슈

  • 변수별 시간해상도 상이 — instant(t2m 등) 6-hourly, tp·복사 hourly. 6h로 통일(precip 합, 복사 평균).
  • solar(ssrd) 폐기 — 6h 샘플 + 1h 누적이라 일적산 깨짐 → CLM longwave energy balance error 크래시 유발. hourly mean shortwave flux 재다운 → 6h 평균으로 교체하여 해결.
  • 1983 wind 결손 — u10/v10 1983년 2월 전체(28일) 누락. 코드에 ntime 체크/skip 권장.
  • datm 스트림 검증 — fileNames에 나열된 모든 연도 파일을 init 때 검증. 미완성/깨진 파일 끼면 즉사.
  • NCL 함정 — &는 좌표연산자뿐(문장 구분자 X); procedure는 global 미참조(인자 전달); 서버 비대화형 ncl은 NCARG_ROOT 필요.

스트림 매핑 (user_datm.streams.txt.CLMGSWP3v1.*): filePath=/data2/.../1_CLM/tmp, fileNames=1979_era5.nc, 변수매핑 GSWP3 그대로 (Solar FSDS swdn / Precip PRECTmms precn / TPQW TBOT tbot · WIND wind · QBOT shum · PSRF pbot · FLDS lwdn). 우리 파일 변수명이 GSWP3와 동일해 매핑 무수정.

10. CESM datm — 외부 대기강제력 연결 방법 (핵심 정리)

I 컴셋(CLM-only)의 대기 입력은 datm(data atmosphere)이 담당. 기본 GSWP3 스트림을 우리 ERA5 파일로 override하는 게 요점. xmlchange만으론 안 되고 user 스트림 파일이 필요.

① 작동 원리 — override

  • CESM 자동생성: CaseDocs/datm.streams.txt.CLMGSWP3v1.{Solar,Precip,TPQW} (읽기전용, preview마다 재생성 — 직접 수정 X)
  • 사용자 사본: case 루트에 user_datm.streams.txt.CLMGSWP3v1.* 두면 datm이 이걸 우선 사용
  • 스트림 이름 CLMGSWP3v1 유지 → 시간보간(Solar=coszen, Precip=nearest, TPQW=linear) 자동 상속

② 수정 절차

cd <case>
# 자동본을 user_ 로 복사 (case 루트)
cp CaseDocs/datm.streams.txt.CLMGSWP3v1.Solar  user_datm.streams.txt.CLMGSWP3v1.Solar
cp CaseDocs/datm.streams.txt.CLMGSWP3v1.Precip user_datm.streams.txt.CLMGSWP3v1.Precip
cp CaseDocs/datm.streams.txt.CLMGSWP3v1.TPQW   user_datm.streams.txt.CLMGSWP3v1.TPQW
chmod u+w user_datm.streams.txt.*

③ 각 user 스트림에서 고친 것 — <fieldInfo> 안 2곳만

④ xmlchange — 연도 정렬

./xmlchange DATM_CLMNCEP_YR_START=1979   # forcing 가용 시작연
./xmlchange DATM_CLMNCEP_YR_END=1979     # 가용 끝연 (다년이면 확대)
./xmlchange DATM_CLMNCEP_YR_ALIGN=1979   # 모델 0001년차 ↔ forcing 1979 매핑
./preview_namelists                       # → CaseDocs에 우리 경로 반영 확인
핵심 포인트
• 우리 파일을 GSWP3 포맷 클론(0.5°·동일 변수명·noleap·NetCDF4Classic)으로 만들었기에 스트림은 filePath/fileNames만 바꾸면 끝. domain·매핑·보간 무수정.
• datm은 init 때 fileNames에 나열된 모든 파일의 time/calendar를 검증 → 미완성·구버전 파일 끼면 즉사.
• YR_END < 적분길이면 datm이 forcing을 자동 cycle(taxMode) → spin-up 반복에 사용.
• 격자 정합: forcing 0.5° ≠ 모델격자(f19/f09)여도 datm이 모델격자로 보간하므로 무방.
